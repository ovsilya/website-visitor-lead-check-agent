What happens on a run

A · On demand, in chat (target)

  1. A Marketing user opens Gemini Enterprise, picks the MDL agent and attaches this week's RB2B export.
  2. GE passes the request to the agent in the Marketing spoke (Cloud Run, via A2A).
  3. The agent scores the file with fixed rules. The file stays in memory and is never saved.
  4. It sends counts, titles and accounts, no names, to Gemini (via the AI gateway) for the short summary.
  5. The user gets the summary in chat and the workbook to download. Arize records the trace.

B · Weekly, automatic (full version)

  1. Cloud Scheduler starts the weekly job in the spoke.
  2. It reads the week's RB2B data (source TBD: upload, export or feed) and checks Salesforce for existing contacts.
  3. Same scoring and same Gemini step as in chat.
  4. One email goes to the lead-triage inbox, which routes leads to client-success owners.

Flow B doesn't touch Gemini Enterprise, so it works even if GE file upload doesn't.

Privacy and access rules (every environment)

  • Uploaded RB2B files are held in memory only, never saved in any project. The workbook is only for the user who ran the check; it downloads once and is deleted then, or after 30 idle minutes.
  • Names, emails and LinkedIn URLs never go to the model; they're only in the workbook.
  • Private only: Google sign-in (IAP) or GE seat; company.example accounts. No public access.
  • No .gcloud/, .env or data in the repo or the image.
